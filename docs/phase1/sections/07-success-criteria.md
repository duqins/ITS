# 7. Measurable Project Success Criteria

<!-- widths: 1900,3000,2200,2260 -->
| Area | Criterion | Target (prototype) | How measured |
|---|---|---|---|
| Functional performance | All Must-have functional requirements implemented and passing tests | 100 % of Must; ≥ 70 % of Should | Requirements traceability matrix; test report (Phase 7) |
| Functional performance | End-to-end workflow: register → publish → request → match → approve → transfer → receipt | Completes without manual database edits | System test scenario |
| User acceptance | Task success and satisfaction in user-acceptance testing | ≥ 90 % task completion; mean SUS ≥ 70 | UAT with ≥ 6 participants across roles |
| Match usefulness | Top-3 semantic match contains a suitable asset (judged by tester) | ≥ 80 % of test requests | Labelled synthetic request set (≥ 30 requests) |
| Match usefulness | Explanation rated understandable and relevant | ≥ 4/5 average rating | UAT questionnaire |
| Classification quality | AI-suggested category accepted by user | ≥ 75 % acceptance | Log of accept/edit/reject on test set |
| Avoided purchases | System records avoided purchases with value | Report produced; calculation traceable | Report validation against sample data |
| Reuse / repair / sustainability | Reuse rate, asset-life extension, waste diversion, carbon estimate computed with stated uncertainty | All five indicators on dashboard and in report | Validation of calculations (Phase 7) |
| Responsible AI | Every high-impact action requires human approval; fallback works with AI disabled | 100 % of workflows | Security/workflow tests |
| Process | Regular individually-authored commits by every member | ≥ 2 meaningful commits/member/week; PR-based merges | GitHub history review |
| Documentation | All eight phase deliverables submitted on time | 8/8 | Course submissions |
